# Website and `omnibioai-auth` License Compatibility

## Assessment

Control Center can use the existing `omnibioai-auth` manual issuance API directly through its current proxy. The website approval flow cannot be declared compatible with that API: its backend contract ends at a Cloudflare Worker PATCH, and no Worker source or response schema is available locally. There is no evidence that website approval currently invokes `omnibioai-auth` at all.

Auth details below describe the current local `omnibioai-auth` worktree. That checkout contains uncommitted changes, including the manual issuance route/service/schema and migration; these findings are therefore current-worktree evidence, not a claim that those changes are deployed.

## Auth issuance contract

`app/api/routes_platform_licenses.py` registers `POST /platform/licenses` (`../omnibioai-auth/app/api/routes_platform_licenses.py:57-90`). It requires an authenticated and authorized license admin, plus `Idempotency-Key`. Request fields are `full_name`, `email`, `persona` (`developer` or `application_user`), `validity_days`, `organization_id`, `confirm_role_change`, and `confirm_replace_existing` (`../omnibioai-auth/app/schemas/license.py:111-119`). Success returns `{license: <metadata>, key: <string|null>, one_time_display: true, idempotent_replay: <bool>}` (`../omnibioai-auth/app/schemas/license.py:121-147`). The full key is available for initial display only; Control Center says it displays and copies the key once (`../omnibioai-control-center/frontend/cc-ui/src/pages/ManualLicensesPage.tsx:33-59`).

Auth generates `OMNI-XXXX-XXXX-XXXX-XXXX`: four groups of four characters chosen using Python `secrets.choice` from `ABCDEFGHJKMNPQRSTUVWXYZ23456789` (`../omnibioai-auth/app/services/license_service.py:23-35`). New keys are stored as an HMAC-SHA256 digest using the configured license pepper, plus a non-secret prefix; the raw key is not stored in the new row and is handed to the issuance response once (`../omnibioai-auth/app/services/license_service.py:42-50, 76-121`; model/migration: `../omnibioai-auth/app/db/models.py:271-293`, `../omnibioai-auth/alembic/versions/0032_manual_license_security.py:16-22`).

Manual issuance requires an existing active user account with the supplied email and active membership in the selected organization; otherwise it returns a provisioning or membership error (`../omnibioai-auth/app/services/manual_license_service.py:155-172`). It sets plan `beta`, platform `both`, max uses `1`, binds the row to the user and organization, and calculates expiry as UTC now plus the requested validity days (`../omnibioai-auth/app/services/manual_license_service.py:217-227`; date calculation in `../omnibioai-auth/app/services/license_service.py:96-121`). Allowed validity values come from `LICENSE_ALLOWED_VALIDITY_DAYS`; there is no default list in code, and issuance is disabled when it is empty (`../omnibioai-auth/app/core/config.py:159-169`; `../omnibioai-auth/app/services/manual_license_service.py:34-46`).

Personas map to IAM roles: `developer` → `scientist`; `application_user` → `org_member` (`../omnibioai-auth/app/services/manual_license_service.py:21-24`). Role assignment is conditional on the explicit confirmation field. Replacing an active license also requires explicit confirmation; earlier active licenses for that identity/org are revoked as part of issue (`../omnibioai-auth/app/services/manual_license_service.py:180-215`). The route does not send email. Control Center returns the key to the authorized operator for copy/display.

Activation occurs through `POST /license/validate`. Newly issued digest-only keys require an authenticated identity; an anonymous compatibility path is limited to legacy plaintext keys (`../omnibioai-auth/app/api/routes_license.py:39-70`). Validation checks key ownership, email, platform, expiration, revocation, and organization membership (`../omnibioai-auth/app/services/license_service.py:137-204`). The first successful use binds `user_id` and increments use count (`../omnibioai-auth/app/services/license_service.py:220-234`). Licenses can expire, be renewed under configured validity policy, and be revoked through the manual license admin API (`../omnibioai-auth/app/api/routes_platform_licenses.py:118-149`). The legacy `POST /license/generate` now returns HTTP 410 instructing clients to use the idempotent platform issuance API (`../omnibioai-auth/app/api/routes_license.py:167-175`).

## Control Center path

Control Center’s `issueLicense()` sends `POST /platform/licenses` with JSON and the `Idempotency-Key` header (`../omnibioai-control-center/frontend/cc-ui/src/licenses.ts:81-87`). Its proxy forwards the bearer Authorization header, idempotency header, body, and upstream response to auth (`../omnibioai-control-center/backend/src/control_center/api/routes_license_admin_proxy.py:14-39, 52-55`). The form collects name, email, persona, validity, organization, and confirmations (`../omnibioai-control-center/frontend/cc-ui/src/pages/ManualLicensesPage.tsx:18-22, 60-75`). This matches the auth issuance request/response contract in the current local worktree.

## Compatibility risks for website reuse

The website approval PATCH supplies only `status` and optional note, and authenticates with `X-Admin-Key`; auth issuance requires a user bearer token, `Idempotency-Key`, a pre-existing active auth identity, organization ID, persona, selected validity, and confirmations. The Worker would need to translate/provision those details and call the auth service through an authorized server-side identity. The website has no organization ID, no auth persona mapping, and no validity selector. The website approval response is ignored, so it cannot safely capture the one-time key returned by auth or confirm that issuance succeeded. Email delivery is absent from auth’s issuance flow and would need an explicitly defined delivery step; the current Control Center contract is manual operator copy, not automatic email.

Until the Worker handler and its deployment configuration are inspected, Control Center’s auth reuse is feasible at the service-contract level, but website issuance compatibility and end-to-end reuse remain unverified. No implementation or live API call was performed.
